# expo-doctor checks that are known-benign in this workspace and must not fail CI.
#
# One check name per line, byte-identical to expo-doctor's "✖ <name>" output.
# scripts/check-expo-doctor.sh fails if expo-doctor reports a failing check whose
# name is NOT listed here — so a new problem is caught, while these stay quiet.
# All of it was diagnosed in #168; please don't re-investigate.
#
#   Check npm/yarn versions
#     Asserts npm >= 3.0.0, which is meaningless here — this workspace is pnpm and
#     nothing in apps/mobile is installed by npm. It fails on any machine where
#     corepack shims `npm` away ("Could not determine npm version"), and unlike the
#     `npm explain` checks below it reaches a real verdict, so it cannot be
#     tolerated automatically. Permanently benign; not worth chasing.
#
#   Check that no duplicate dependencies are installed
#     apps/web's react@19.2.8 seen from apps/mobile's react@19.2.3 — the
#     intentional monorepo split, not a duplicate inside mobile's own tree. Web is
#     live in production on ^19.3.0; SDK 57 pins mobile to 19.2.3 exactly, to match
#     react-native's renderer. See the `react` note at the end of dependabot.yml.
#
#   Check that packages match versions required by installed Expo SDK
#     The deliberate expo pin (docs/decisions.md, 2026-08-10). Timer-bound: it
#     clears itself when Dependabot bumps the expo group. Delete this line then —
#     the script does not care if a listed failure stops happening.
#
#     ⚠️ KNOWN GAP, and it has cost us twice. This entry suppresses the check for
#     EVERY package it covers, not just expo's own. That is how two Dependabot
#     leaks of apps/mobile's `react` pin reached main green and unnoticed: #275
#     took it 19.2.3 -> 19.2.8, and #326 took it 19.2.8 -> 19.3.0, a full MINOR
#     ahead of the renderer react-native 0.86.x expects. Restored to 19.2.3 on
#     2026-09-14. `react` cannot be Dependabot-ignored (ignores are
#     workspace-wide and would freeze apps/web, which is live) — so until this
#     check is made per-package, the ONLY thing standing between a grouped
#     `misc` bump and an SDK-mismatched renderer is reading the diff. On any
#     misc-group PR:
#       gh pr diff <n> | grep -E '^[+-].*"(react|react-dom|@types/react)"'
#     and drop the apps/mobile hunks before merge.
#
#     Still-open drift this check is currently hiding: react-native 0.86.2
#     installed vs 0.86.3 wanted by expo 57.0.20's bundledNativeModules.
#
# Deliberately NOT listed: the three checks that shell out to `npm explain` (support
# packages, legacy global CLI, vector-icons). They fail for the same corepack reason,
# but expo-doctor reports them as "Unexpected error while running '<name>' check:"
# rather than as a verdict, and the script tolerates any check that errored out that
# way. Listing them would give up a real gate — they each detect something worth
# detecting — for no gain, since the tolerance already covers every runner. Observed
# both ways on one machine in one session: 6 failing checks with npm shimmed, 2 once
# corepack had provisioned a real npm.

Check npm/yarn versions
Check that no duplicate dependencies are installed
Check that packages match versions required by installed Expo SDK
